# Troubleshooting — Computational Issues and Fixes

This document records significant issues encountered during the setup and
execution of the curcuminoid–cyclodextrin molecular docking, MD, and
MM/PBSA workflow, along with their solutions.

**Scope:** Only issues that a reader reproducing the workflow is likely to
encounter, or that reveal a non-obvious methodological pitfall, are included.
Setup-specific environment problems are documented in the corresponding
notebooks.

---

## 1. CHARMM-GUI

### 1.1 β-CD residue naming — `AGLC` vs `BCD`

**Symptom**

`gmx_MMPBSA` fails with:

```
Complex nres != receptor nres + ligand nres
```

even though the topology files were generated by the same CHARMM-GUI
workflow.

**Cause**

CHARMM-GUI assigns **different residue names** to β-CD depending on which
reader is used:

| Reader | Residue name for β-CD |
|--------|----------------------|
| **Ligand Reader & Modeler** | `BCD` |
| **Glycan Reader & Modeler** | `AGLC` (one per glucose unit) |

If the complex is built via **Ligand Reader** but the free β-CD is built via
**Glycan Reader**, the two topologies will not match — even though the
underlying molecules are identical.

**Fix**

Rebuild the free β-CD system using the **same reader** as the complex —
i.e. upload the same `bcd.mol2` file through **Ligand Reader & Modeler**.
This forces the residue name to be `BCD` consistently.

> **Rule of thumb:** Within a single project, always use the **same reader**
> for the same molecule across complex, free host, and free guest runs.

### 1.2 Glycosylation box auto-checked for β-CD

**Symptom**

CHARMM-GUI silently treats the free β-CD as a **glycan** to be attached to a
protein, producing an incorrect topology that fails at the GROMACS stage.

**Cause**

CHARMM-GUI's Glycan Reader has an **auto-checked** "Glycosylation / Glycan
Ligand(s)" option that gets enabled when it recognizes sugar-like structures.

**Fix**

**Uncheck** the glycosylation box before submission. For a free cyclodextrin,
the molecule is a **standalone host**, not a glycan ligand attached to a
protein.

### 1.3 Hypervalent carbon error

**Symptom**

CGenFF parameterization fails with a valence error.

**Cause**

A carbon atom in the uploaded MOL2 file had 5 bonds — a common problem with
aromatic or conjugated systems when converting from PDB or SMILES without
proper bond perception.

**Fix**

Manually edit the MOL2 file: change one bond (typically a double bond flagged
as type 2) to a single bond (type 1) so the carbon has the correct valence.

## 2. GROMACS

### 2.1 Production run finishes far sooner than 100 ns

**Symptom**

Production MD ends after ~1 ns instead of the intended 100 ns.

**Cause**

The CHARMM-GUI default `step5_production.mdp` uses:

```
nsteps = 500000     ; 1 ns at dt = 2 fs
```

**Fix**

Edit `step5_production.mdp`:

```
nsteps = 50000000   ; 100 ns at dt = 2 fs
```

Then rebuild the `.tpr` with `gmx grompp`.

### 2.2 PBC wrapping — molecules split across the box

**Symptom**

In VMD, the host or guest appears fragmented across the periodic box, or
"jumps" to the opposite side mid-trajectory.

**Cause**

GROMACS writes trajectories in the original simulation box. Molecules that
cross a box boundary are written with coordinates outside the central box.

**Fix**

Post-process the trajectory with `gmx trjconv`:

```bash
gmx trjconv -s step5_production.tpr \
    -f step5_production.xtc \
    -o step5_production_fixed.xtc \
    -pbc mol -center
```

**Prompts:**
- **Centering group:** the host–guest complex (e.g. `Complex` or `SOLU`)
- **Output group:** `System`

The resulting `_fixed.xtc` keeps every molecule whole and centered across
all frames.

> **Note:** Do **not** use VMD's `animate write xtc` for this — it produces
> a non-native XTC variant that may be rejected by `gmx_MMPBSA`. Always use
> `gmx trjconv`.

### 2.3 VMD `pbc wrap` — residue name not found

**Symptom**

In VMD's TkConsole:

```
selection "resname BCD" is empty!
```

**Cause**

The residue name in the loaded trajectory is not `BCD`. It may be `AGLC`
(if the system was built via Glycan Reader) or something else.

**Fix**

Find the actual residue name:

```tcl
set sel [atomselect top "all"]
$sel get resname
```

Then use that name in the `pbc wrap` command.

### 2.4 VMD `pbc wrap relax` — unknown option

**Symptom**

```
pbcwrap: unknown option: relax
```

**Cause**

`-relax` is not a valid option in VMD 2.0.0a6 — it exists only in some
older builds.

**Fix**

Use:

```tcl
pbc wrap -compound fragment -center com
```

## 3. gmx_MMPBSA

### 3.1 Charge mismatch — `Inconsistent charge definition for atom X`

**Symptom**

`gmx_MMPBSA` aborts during setup with:

```
Inconsistent charge definition for atom 37
```

**Cause**

The complex and free-ligand topologies were generated by **different
CHARMM-GUI submissions**, and CHARMM-GUI assigned slightly different
**atom types** and **partial charges** to the same atom. This is invisible
during MD (each topology is internally consistent) but breaks multiple-
trajectory MM/PBSA because the method requires the complex topology to
equal receptor + ligand exactly.

**Diagnosis**

Compare the guest topology in the two folders:

```bash
diff complex/toppar/CUR.itp ligand/toppar/CUR.itp
```

If atom X differs in the atom-type and charge columns, that's the culprit.

**Fix**

The proper fix is to **rebuild both systems from the same CHARMM-GUI
submission** — or to ensure the guest `.itp` used in the complex and in
the free-ligand runs is **byte-identical**.

>  **Do not** hand-edit a single atom's charge or atom type to force a
> match. This introduces a force field that was never used to generate the
> trajectory and produces physically meaningless energies. See the note in
> the project log for the full reasoning.

### 3.2 Missing `toppar/` folder in receptor / ligand subfolders

**Symptom**

```
PreProcessorError: Could not find toppar/forcefield.itp
```

**Cause**

The `#include "toppar/forcefield.itp"` directive in each `.top` file is
resolved **relative to that `.top` file's directory**. If `toppar/` is only
present next to the complex `.top`, the receptor and ligand `.top` files
cannot find it.

**Fix**

Copy the `toppar/` folder into **each** subfolder that contains a `.top`:

```
mm_pbsa/
├── complex/
│   ├── complex.top
│   └── toppar/
├── receptor/
│   ├── receptor.top
│   └── toppar/
└── ligand/
    ├── ligand.top
    └── toppar/
```

### 3.3 `PBRadii` compatibility error

**Symptom**

```
PBRadii=7 is compatible only with &pb!
```

**Cause**

`PBRadii=7` (CHARMM radii) was specified in `&general` while running an
**MM/GBSA** (`&gb`) calculation. CHARMM radii are only valid for **MM/PBSA**
(`&pb`).

**Fix**

For MM/GBSA: **remove** the `PBRadii=7` line from `mmpbsa.in`.

For MM/PBSA: place it inside the `&pb` namelist:

```
&pb
  PBRadii=7, istrng=0.15,
/
```
